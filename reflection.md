# Reflection: The GIGO Principle and Prompt Engineering

This project was a masterclass in the GIGO (Garbage In, Garbage Out) principle. Before this assignment, my mental model of interacting with a Large Language Model was essentially treating it like a search engine—giving it a brief instruction and expecting it to do the heavy lifting. My early iterations of these personas reflected that flaw. A basic prompt like "Act as Anshuman Singh and teach DSA" yielded a generic, overly enthusiastic AI assistant that sounded nothing like the intense, first-principles-driven founder of InterviewBit. The output was garbage because the input lacked depth, constraints, and context.

Applying the GIGO principle taught me that an LLM is a reasoning engine, not a mind reader. To get a highly specific output, I had to provide a highly constrained, data-rich input. By feeding the model Anshuman's specific background at Facebook Messenger, Abhimanyu's experiences at Fab.com, and Kshitij's legendary "mark-sheet" classroom demeanor, the AI had the contextual anchors needed to generate authentic responses.

The most successful technique I implemented was the Chain-of-Thought (CoT) instruction via the `<thought>` tags. Forcing the model to explicitly reason about the student's underlying misconception *before* generating the final text completely changed the output quality. Instead of immediately giving away the answer, the CoT step forced the LLM to adhere to the "Socratic guide" constraint. This was especially effective for Kshitij's persona, where the CoT step allowed the model to plan its "calm sarcasm" without crossing the line into cruelty.

On the frontend, writing the parsing logic to hide these `<thought>` tags from the user interface was a great exercise in marrying prompt engineering with UI/UX design. It allowed the backend to do heavy, messy reasoning while keeping the user-facing product clean and professional.

Looking back, while the persona switching and prompt constraints worked beautifully, there is room for improvement. If I were to iterate on this, I would focus on preventing context degradation. Currently, if a user asks 15 consecutive questions, the LLM's context window fills up, and it might start "forgetting" the strict constraints of the initial system prompt. To solve this, I would implement a rolling window for the chat history, ensuring the system prompt and the most recent, relevant context always take priority. Additionally, integrating Retrieval-Augmented Generation (RAG) to pull from actual Scaler class transcripts would elevate the bot from a behavioral simulator to a truly authoritative educational tool.
